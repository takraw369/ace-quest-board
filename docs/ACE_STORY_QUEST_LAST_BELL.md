# ACE Story Quest 001 — 鳴らなかった、最後の鈴

## 目的と配置
既存 ACE Quest Board のアプリ内に /quest/stories/last-bell を設置する。別アプリ・追加課金・新しいデータベースは作らない。

- 最初の印象（棄権／気づき／保留）
- アナグラム RACE → CARE から調査の視点を選ぶ
- ナギ本人に話を聞く／大会記録を調べる
- 読みが反転しうるエピローグ、ただし人物の真意は確定させない
- 自由コメントを端末に保存し、一覧／編集／削除／再読取ができる

## 保存とプライバシー
v0 は **localStorage（同一端末・同一ブラウザのみ）**。共有掲示板ではない。アカウント同期、他者への公開、サーバー送信、Drive 自動取込は行わない。
鍵: ace_story_001_comments_local_v1。各コメントに id / body / createdAt / updatedAt / firstImpression / drawer / investigation を保存。本文は空白除外、最大1200文字。最新100件。
内容はクライアントの React text rendering 経由で表示。任意 HTML を描画しない。保存失敗時は成功表示しない。編集・削除は本人の端末で実施。
コメントへの「いいね」や多数派への誘導は導入しない。最初の推論を評価せず、解釈の多様性と判断保留を許す。

## 共同コメントに進む際の Human Gate
本実装から他者が読める機能へ変更する場合は **別途レビューと明示承認が必要**。以下が揃うまで「投稿して他者に見せる」UIにしない。

1. 既存 Supabase / ACE 認証に結びつく story_id・comment_id・user_id を定義、個人別の書込／編集／削除に RLS を適用する。匿名自由書込やクライアントへの service-role 公開は禁止。
2. 表示名・公開範囲・投稿前確認を分ける。本人の同意なしに今回の会話文やローカルメモを公開しない。
3. 迷惑投稿や個人情報露出に備えた通報・非表示・モデレーション方針と、未成年が利用しうることを前提とした安全設計を検討する。
4. コメント未読でも物語を体験でき、閲覧タイミングを選べるようにする（先読みで解釈を誘導しない）。
5. 投稿数や人気順を学習成果と同一視せず、仮説の変化・判断保留・別の視点への気づきを個別に検証する。

## テストと公開ゲート

- npx playwright test tests/e2e/story-quest-comments.spec.ts
- 320px / 375px 実画面確認、コメント保存・再訪・編集・削除、異なるルートの再体験
- 本番の自動公開へ接続された dev には、CIとプレビュー画面の確認後、オーナーが承認するまで **mergeしない**。

## 教育上の検証問い
新たな手がかりに出会った際、プレイヤーは自分の最初の読みを自律的に見直したり、判断を保留したりできるか。

注：ユーザーが最初に提示した「体育館との別れを始めたくなかった」という解釈は重要な制作上の発見。ただし作者の正解や登場人物の確定動機として本文に埋め込まない。
